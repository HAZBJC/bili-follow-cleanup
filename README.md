# B站关注清理助手

一个 Tampermonkey 用户脚本：扫描你的 B 站关注列表，找出"一年以上没更新"和"已注销"的UP 主，导出清单供你核对，确认后再按可控节奏取消关注。

> 默认只读。扫描阶段不会关注、也不会取关任何账号。

---

## 为什么需要它

B 站关注上限是 5000 个。用得久了，列表里会堆满早就停更的 UP 主、注销的账号、一时冲动关注的号，而 B 站本身没有「按最后更新排序」这种功能，翻 200 多页手动看一遍完全不现实。

这个脚本把这件事变成三步：**扫描 → 核对清单 → 分批取关**。

## 功能

- **两类判定**：`一年以上未更新`、`已注销`
- **只读优先**：扫描阶段只发查询请求，不动你的关注关系
- **限速 + 随机抖动**：模拟正常浏览节奏，避免触发风控
- **风控自动暂停**：命中 `-412` / `-352` 立刻停下来，不会闷头乱撞
- **每日取关上限**：脚本内置每日额度，跑满自动停，跨天自动重置
- **断点续跑**：进度存在 `localStorage`，关页面/刷新后可以接着跑
- **导出 CSV**：完整报表，可以自己再筛一遍
- **导出 / 导入进度**：换电脑不用重扫
- **零依赖**：不加载外部脚本，不引入第三方库（wbi 签名和 MD5 都是内联实现）

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)（Chrome / Edge / Firefox）
2. 点下面的链接安装脚本：

   ```
   https://raw.githubusercontent.com/HAZBJC/bili-follow-cleanup/main/bili-follow-cleanup.user.js
   ```

   Tampermonkey 会自动弹出安装页；或者把 `.user.js` 文件直接拖进浏览器窗口。
3. 登录 B 站，打开你的关注页：

   ```
   https://space.bilibili.com/<你的UID>/relation/follow
   ```

   页面右上角会出现控制面板。

## 使用

### 第一步：扫描

点「开始/继续扫描」。脚本会：

1. 分页拉取关注列表（每页 50 条）
2. 逐个查询每个 UP 主的最新投稿时间
3. 实时更新统计：已查数量、一年未更、已注销、无视频投稿、异常

5000 个关注大约需要 **3–4 小时**（每次请求间隔 1.5–3.2 秒）。可以最小化窗口，但**别关标签页**。中断了再点一次会从断点继续。

### 第二步：核对

面板下方只列出「待取关」的账号，按最后更新从旧到新排列。建议点「导出 CSV」拿完整报表过一遍。

### 第三步：取关

点「按清单取关」，弹窗会告诉你本批多少个、其中一年未更/已注销各多少。确认后才真正执行。

- 每个间隔 6–11 秒
- 每日上限 150 个，跑满自动停
- 弹窗是原生 `confirm()`，会短暂阻塞页面，属正常现象

## 判定规则与局限

| 判定 | 依据 | 局限 |
|---|---|---|
| 一年未更新 | 最新视频的 `created` 早于 365 天前 | **只判断视频投稿**，不判断动态/图文 |
| 已注销 | 昵称包含「账号已注销」 | 启发式判定；有人会把昵称改成这个来玩梗 |
| 无视频投稿 | 空间投稿列表为空 | 单独标出，**不算**未更新，需人工判断 |

关于「已注销」为什么不用接口状态判断：B 站对已注销账号通常**不返回 `-404`**，而是照常返回其历史视频列表，所以只能靠昵称兜底。这意味着：

- 昵称改回正常名字的注销号会漏掉
- 单纯把昵称改成「账号已注销」的活人会误判

两种情况都很少见，但属于已知误差。

## 风控说明

B 站对关注/取关操作有频率和次数限制，超限会返回 `-352`（风控校验失败）或 `-412`（请求被拦截），严重时会要求验证码甚至临时封禁。

脚本默认参数：

| 参数 | 默认值 | 位置 |
|---|---|---|
| 扫描间隔 | 1500–3200 ms | `CFG.scanDelayMin/Max` |
| 取关间隔 | 6000–11000 ms | `CFG.unfollowDelayMin/Max` |
| 每日取关上限 | 150 | `CFG.dailyUnfollowCap` |
| 判定阈值 | 365 天 | `CFG.yearMs` |

觉得快就改大 `CFG` 里的数值，改完刷新页面生效。**不建议**把取关间隔降到 3 秒以下。

## 隐私

- 所有数据只存在你浏览器的 `localStorage` 里，**不上传到任何服务器**
- 脚本只读取你自己的关注列表和登录态，不发往第三方
- 导出的 CSV / JSON 都保存在本地
- 脚本不包含任何统计、埋点或远程上报代码

## 常见问题

**Q：扫到一半停了，是不是要重来？**
不用。进度存在本地，点「开始/继续扫描」会接着跑。如果显示「已暂停」，通常是命中风控，建议等 1–2 小时再继续。

**Q：为什么「已注销」是 0 个？**
先确认用的是最新版脚本（1.1.0+ 才有昵称兜底判定）。旧版本只认 `-404`，而 B 站基本不返回这个码。

**Q：取关能撤销吗？**
不能。取关是即时生效的，只能重新关注（如果对方还接受关注）。

**Q：为什么每天只能取关 150 个？**
按天分批是为了控制风控风险。改 `CFG.dailyUnfollowCap` 可以调整，但请自行承担风险。

**Q：换电脑还能继续吗？**
可以。在旧机器点「导出进度」，把 `.json` 和新机器上的脚本一起带走，在新机器点「导入进度」。`localStorage` 不跨设备同步，所以必须手动搬。同一天换机时，当日已用额度会一并带过去，避免重复超额。

**Q：为什么不用 B 站客户端/第三方工具？**
脚本复用你浏览器现有的登录态，不接触你的密码，也不需要单独的授权流程。这也是它只在前台页面运行的原因。

## 开发

单个文件，无构建步骤。内联实现了两处核心逻辑：

- **wbi 签名**（`/x/space/wbi/arc/search` 必需）：从 `nav` 接口取 `img_key`/`sub_key`，按 64 位重排表生成 `mixin_key`，对排序后的 query 做 MD5 得到 `w_rid`
- **MD5**：无依赖的纯 JS 实现，支持 UTF-8

改完直接刷新页面即可，Tampermonkey 会加载新版本。
